# 通用闭环骨架：设目标 → 反馈搜索 → 独立验证 → 全局复核

> 从 CompressionBench 抽象出的与目标域无关的四步骨架。抽象依据见 key-finding.md / metrics.md。

## 骨架（与目标域无关）

```
[Step 1 设目标]  可度量目标 + 资源约束 + 环境 + 截止时间
      ↓
[Step 2 反馈搜索]  用反馈信号引导方案迭代，记录每轮候选
      ↓
[Step 3 独立验证门禁]  冻结最终方案 → 独立验证器一次终检 → pass / reward=0
      ↓
[Step 4 全局复核]  局部指标排名 vs 完整反馈 → 标出被推翻项 → 以全局为准
```

## 各步的设计原则（溯源论文）

| 步 | 论文依据 | 抽象原则 |
|---|---|---|
| 设目标 | terminal-task：checkpoint/存储上限 C/环境/时间预算 T | 目标必须可度量、约束明确、截止时间固定 |
| 反馈搜索 | "perplexity feedback guides search" | 反馈信号引导迭代，并记录轨迹（论文 "Full records"）|
| 独立验证 | "independent verification checks the final model"；隐藏 Verifier 一次性终检 | 验证器与生成器上下文隔离；硬门禁一票否决（reward=0）|
| 全局复核 | "complete-model feedback reverses 17 of 79 prior local rankings" | 局部指标默认不可信，必须完整复核；多维度验证（生成/推理测试暴露似然遗漏的失败）|

## 关键判据（本技能价值核心）
- **局部指标不可信**：完整反馈会推翻大量局部排名（论文 17/79）。
- **单一指标可能漏检**：即使完整，似然类指标也会漏掉生成/推理能力缺陷——验证要多维。
- **独立验证是底线**：生成器自评不算数，须上下文隔离的独立验证器。
- **一票否决**：硬门禁不达标即 reward=0，不用其他指标补偿。

## 与目标域无关性的边界
- 骨架可迁移到提示词优化、参数调优等低风险任务（dogfood 场景）。
- 但"局部指标被推翻"的具体比例（17/79）是压缩域实证，不能直接套到其他域——迁移时标"待验证"。
