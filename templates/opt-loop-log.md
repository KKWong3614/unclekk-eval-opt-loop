# 迭代记录模板（opt-loop-log）

> 记录每一步：目标 / 反馈 / 候选 / 验证结果，形成可审计的闭环轨迹。论文强调"Full records"——记录每次修订与轨迹。

## 模板

```markdown
# 优化闭环迭代记录 — [任务名]

## 任务契约（见 terminal-task-spec.md）
- 目标：[可度量目标 + 指标]
- 约束：[预算/硬门槛]
- 环境：[固定环境]
- 截止时间 T：[...]
- 反馈信号：[子集得分 / 代理指标 / perplexity]
- 独立验证器：[描述 + 隔离方式]

## 迭代轨迹
| 轮次 | 候选方案 | 局部反馈得分 | 全局复核得分 | 门禁结果 | 备注 |
|---|---|---|---|---|---|
| 1 | [方案A] | [局部指标] | [完整反馈] | pass / reward=0 | |
| 2 | [方案B] | | | | |
| ... | | | | | |

## 被局部指标误导的案例
- 局部排名 Top：[方案X]；全局复核后实际最优：[方案Y]；是否被推翻：是/否
- （对应论文：完整反馈推翻 79 个局部排名中的 17 个）

## 最终方案
- 选中方案：[...]
- 独立验证结果：[pass/reward=0 + 关键指标]
- 全局复核结论：[...]

## 诚实披露
- 证据范围：[低风险小任务验证 / 目标域验证]，非论文压缩实验（本机无 H200）
- 待验证项：[如判据泛化性、RSI 复利]
```

## 使用要点
- 每轮都记录局部反馈与全局复核两列——这是"局部不可信"判据的数据基础。
- 门禁结果只有 pass / reward=0 两种（对应论文硬门禁）。
- 若某轮局部 Top 被全局复核推翻，必须单列，这是本技能价值的核心证据。
